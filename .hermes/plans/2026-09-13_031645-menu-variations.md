# Menu Variations Implementation Plan

> **For Hermes:** Implement this plan task-by-task on a new feature branch, verifying each task before starting the next.

**Goal:** Let admins configure menu-specific variation groups and price adjustments, and require cashiers to choose those variations in an accessible modal before adding configured products to an order.

**Architecture:** Store variation groups inside each immutable `MenuVersion`, then snapshot chosen option labels, IDs, and surcharges into each `CartLine`. Reuse the existing localStorage-backed store, `Modal`, menu versioning, totals calculator, and order snapshot flow; no new package, server, API, or generalized modifier engine.

**Tech Stack:** React 18, TypeScript, existing store/reducers, localStorage, Vitest, Testing Library, existing CSS tokens/components.

---

## Problems captured from the request

- Cappuccino must support options such as **Less sugar** with no extra charge.
- Paid choices such as **1 extra shot** must increase the line price and all downstream totals.
- Clicking a menu with configured variations must open a customization modal before adding it.
- Menus without variations should retain the current one-click add behavior.

## Current evidence from code inspection

- `src/domain.ts`: `MenuVersion` owns versioned menu data but has no variations; `CartLine` has only a free-text `modifier`; `calculateTotals` trusts the line's unit `price`; `cartReducer` merges only plain lines.
- `src/pages/AdminMenuPage.tsx`: menu creation/editing already creates immutable versions and edits ingredients/components in an existing modal.
- `src/pages/OrderEntry.tsx`: product cards currently dispatch `add` immediately. A later cart-edit modal uses hard-coded modifier strings and does not alter price.
- `src/store.tsx`: catalog and order data persist in `light-pos-demo-v1`; completed/held orders snapshot cart lines.
- `src/App.test.tsx` and `src/domain.test.ts`: existing coverage proves menu versioning, cart totals, historical snapshots, modal accessibility, and one-click ordering.
- Repository is clean but currently on unrelated branch `fix/responsive-forms-expenses` at `c3f0dae`; implementation must start from the appropriate updated base on a new feature branch.
- Codex inspection was attempted with requested `gpt-5.6-sol`/medium, but the configured 9Router endpoint returned `404 No active credentials for provider: openai`; this plan therefore uses verified direct repository inspection.

## Confirmed product decisions

1. Variations are menu-specific and versioned with the menu.
2. A group can be required or optional and single-select only for this scope.
3. Each option has a label and non-negative price adjustment; zero means free.
4. A configured item opens the modal before cart insertion; an unconfigured item remains one tap.
5. The cart/order snapshots the selected options and final unit price so later menu edits cannot rewrite history.
6. The customization modal includes quantity; the existing ledger quantity controls remain available afterward.

## Minimal data shape

```ts
export interface VariationOption {
  id: string;
  name: string;
  priceDelta: number;
}
export interface VariationGroup {
  id: string;
  name: string;
  required: boolean;
  options: VariationOption[];
}
export interface SelectedVariation {
  groupId: string;
  groupName: string;
  optionId: string;
  optionName: string;
  priceDelta: number;
}

// MenuVersion
variations?: VariationGroup[];

// CartLine
basePrice: number;
variations?: SelectedVariation[];
```

`CartLine.price` remains the snapshotted final unit price (`basePrice + selected priceDelta values`) to preserve current totals and historical consumers. Legacy lines without `basePrice` or `variations` continue to render and calculate unchanged.

## Deliberate cuts

- No multi-select groups, min/max selection counts, option stock, nested options, cross-menu reusable modifier library, backend service, or ingredient consumption changes.
- Add those only when a concrete workflow requires them; the current product is localStorage-backed and single-select satisfies the supplied examples.

## Risks and safeguards

- **Historical repricing:** avoided by snapshotting labels, deltas, base price, and final unit price into `CartLine`.
- **Legacy localStorage:** all new menu and line fields are optional; existing records remain readable.
- **Duplicate line merging:** use a stable selection signature; do not merge differently configured lines.
- **Admin input corruption:** trim names and reject empty, duplicate, negative, or non-finite values at save.
- **Interaction regression:** preserve long press, pointer-cancel, Shift+Enter details, sold-out state, and direct add for plain products.
